# Genealogy Biography — навичка для родинної історії за документами

Мови: [English](README.md) / [Русский](README.ru.md) / [Українська](README.uk.md) / [Deutsch](README.de.md)

**Навичка (Agent Skill) для Claude Code, яка пише біографію предка за архівними документами й публікує її сторінкою сайту з історії родини.** Зазвичай на вході — хронологічна таблиця (один рядок — одна подія життя: народження, шлюби, смерті, переписи, сповідні розписи, хрещення як хрещеного батька чи матері, переїзди, зміна стану), але підійдуть і нотатки, посилання чи скани. На виході — зрозуміла розповідь про життя людини, де кожен факт має джерело, а кожна цитата дослівна, і окрема сторінка на кожен документ.

Навичку створено для російськомовного сайту на [MkDocs Material](https://squidfunk.github.io/mkdocs-material/) про родини з Російської імперії та СРСР. Інструкції в ній написані англійською, а текст для сайту вона пише російською (або мовою, яку ви попросите); цитати з документів зберігають дореформений правопис оригіналу.

---

## Що вона робить

- **Сторінка біографії.** Розповідь про життя за періодами, список родини, хронологія, зауваги про розбіжності між документами й окремий блок дослідницьких нотаток для припущень.
- **Сторінки джерел.** По сторінці на кожен документ: повний архівний шифр (архів, фонд, опис, справа, аркуш), де зберігається скан, назви граф бланка, дослівний текст запису й пояснення до непевних прочитань. Сторінка одна на документ, навіть якщо він потрібен кільком біографіям.
- **Дослівні цитати.** Записи цитуються точно, з первісним правописом. На сторінці джерела сказано, звідки взято текст: прочитання скану, розшифровка укладача, розшифровка інших дослідників (з посиланням) чи розпізнавання Яндекс Архіву. Непевне слово позначено `[?]`, нечитабельне місце — `[…]` або `[неразборчиво]`.
- **Помічник для Яндекс Архіву.** `scripts/yandex_archive.py` бере розпізнаний текст і архівний шифр скану та шукає в архіві. Розпізнаний текст — чернетка: його звіряють зі сканом, виправлення показують.
- **Постійні ідентифікатори.** Кожна сторінка має постійний ID (`P1000` — людина, `A1000` — архівний запис, `B` — книга, `F` — фото, `W` — вебсторінка, `PLC` — місце…). `scripts/next_id.py` видає наступний вільний ID і перевіряє, чи документ уже має сторінку, — тож нічого не дублюється.
- **Покажчик імен.** Кожен, кого названо в записі про людину, — рідні, хрещені, свідки, сусіди, священники — отримує рядок у спільному покажчику; жінки — під кожним відомим прізвищем.
- **Місця.** Людей пов'язано зі сторінками населених пунктів. Сторінка місця починається з церковної парафії за періодами, далі — дореволюційний адміністративний поділ за періодами (наприклад, губа XVIII століття, потім повіт і волость) і таблиця всіх згадок місця в документах за роками, щоб було видно зміни назв і розбіжності.
- **Сувора збірка.** Наприкінці сайт збирається в суворому режимі: зламане посилання чи невідомий ID зупиняють роботу, доки їх не виправлять.

## Яких правил вона дотримується

- **Нічого не вигадувати.** Жодних імен, дат, родичів, шифрів і цитат, яких немає у вхідних даних. Якщо документи мовчать, так і написано.
- **Кожен факт із посиланням,** і посилання веде до потрібного запису, а не до оглядової сторінки.
- **Висновки позначено.** Гіпотеза потрапляє до дослідницьких нотаток і починається словами «Предположение (не подтверждено документами)», з аргументами за і проти та з тим, що може її підтвердити.
- **Спорідненість — за ланками.** Кожен зв'язок «батько чи мати — дитина» та «чоловік — дружина» має власні джерела; далекий предок доведений, лише якщо доведена кожна ланка. Копії одного запису — одне джерело. По батькові називає ім'я батька, але не показує, яка це людина; спільне прізвище, село чи двір — не доказ спорідненості.
- **Тезки окремо.** Двох людей з однаковими іменем і по батькові з одного села не об'єднують, доки документи їх не розрізнять.
- **Розбіжності не приховують.** Обидві версії наводять поруч — із тим, хто й коли повідомив відомості.
- **Відсутність запису — не доказ,** що події не було; на сторінці сказано, які книги й роки переглянуто.
- **Кожен перегляд архіву записується,** і з находкою, і без неї, до внутрішнього реєстру (`internal/checks/reviewed_documents.md`), щоб через роки не шукати те саме знову.
- **Робоча таблиця на сайті не згадується:** читач бачить лише справжні джерела.

## Що потрібно

- [Claude Code](https://claude.com/claude-code) або інше середовище з підтримкою Agent Skills.
- Python 3 (лише стандартна бібліотека).
- Сайт з очікуваною структурою: `family_tree_github/` з папками `docs/people/`, `docs/sources/{archives,books,photos,websites}/`, `docs/places/`, покажчиками та `mkdocs.yml`, а також хук посилань за ID (`hooks/id_links.py`). Шляхи прописано в навичці; для іншого сайту виправте таблицю «Where the output goes» у `SKILL.md` і шлях `DOCS` у `scripts/next_id.py` (або задайте змінну середовища `DOCS`).
- За бажанням — навичка **chronology-table**: вона читає хронологічні таблиці `.ods`, `.xlsx`, `.csv` і підключається сама, якщо на вході таблиця.

## Встановлення

Навичка входить до набору [genealogy-skills](https://github.com/usuyukiso/genealogy-skills). Склонуйте набір і скопіюйте цю папку разом із **chronology-table**, якою навичка читає таблиці (назва папки — це назва навички):

```bash
git clone https://github.com/usuyukiso/genealogy-skills ~/genealogy-skills
cp -r ~/genealogy-skills/genealogy-biography ~/genealogy-skills/chronology-table <проєкт>/.claude/skills/
```

або до особистих навичок (`~/.claude/skills/`), щоб користуватися ними в усіх проєктах. Про інші навички та те, як вони працюють разом, — у README набору.

## Як користуватися

Навичка запуститься сама, якщо ваше прохання їй підходить, — просто опишіть завдання в Claude Code (або запустіть напряму: `/genealogy-biography`), наприклад:

- *«Напиши біографію Євдокії Лапіної за таблицею `sources/people_all.xlsx`»*
- *«Онови сторінку Григорія Писарева: додай донесення про втрати 1943 року з цитатою»*
- *«Напиши біографію за цими трьома сканами метричних книг у Яндекс Архіві»*

Помічники можна запускати й вручну з кореня проєкту:

```bash
python3 .claude/skills/genealogy-biography/scripts/next_id.py next A A P          # наступні вільні ID
python3 .claude/skills/genealogy-biography/scripts/next_id.py find "23И, оп. 2, д. 24"  # уже є на сайті?
python3 .claude/skills/genealogy-biography/scripts/yandex_archive.py page "<посилання на скан>"
python3 .claude/skills/genealogy-biography/scripts/yandex_archive.py search "Лапина Корсаковск"
```

Наприкінці агент повідомляє, які сторінки написав і які використав повторно, скільки людей додано до покажчика, які записи процитовано за сканами, які не мають тексту, і які розбіжності варто перевірити.

## Файли

| Шлях | Призначення |
|---|---|
| `SKILL.md` | Інструкції, яких дотримується агент |
| `references/terms.md` | Розшифрування скорочень архівів (ГИАСО, РГИА ДВ…) і термінів записів; поповнюється під час роботи |
| `scripts/next_id.py` | Наступний вільний ID, пошук дублікатів, список усіх ID |
| `scripts/yandex_archive.py` | Розпізнаний текст і шифр скану Яндекс Архіву; пошук в архіві |

## Обмеження

- У машинному розпізнаванні (Яндекс Архів) бувають помилки в іменах, числах і датах; навичка позначає такий текст і просить звірити його зі сканом.
- Навичка пише лише те, що підтверджують вхідні дані. Сама вона шукає лише в Яндекс Архіві; пошук нових записів — окрема дослідницька робота.
- Живі люди: сайт відкритий, тож публікуйте лише те, на що погоджується родина.
